# QUAD Integration Test Plan

**Date:** January 15, 2026
**Status:** Ready for Testing
**Integration:** Context Memory + AI Router + Hooks

---

## Overview

This test plan validates the complete integration of:
1. **Pre/Post Hooks** - Capture context before/after commands
2. **AI Router** - Smart routing between Gemini/Claude with confidence fallback
3. **Context Memory** - Store and retrieve project/preferences context
4. **Config System** - Manage AI provider configuration

---

## Test Scenarios

### Scenario 1: Fresh Installation

**Goal:** Verify complete setup from scratch

**Steps:**
```bash
# 1. Install QUAD CLI
cd QUAD/quad-cli
pip3 install -e .

# 2. Verify installation
quad --version

# 3. Check AI config status (should show not configured)
quad config status
```

**Expected:**
- QUAD CLI installed successfully
- Config shows: Gemini ✗ Not Set, Claude ✗ Not Set
- Router mode: smart (default)

---

### Scenario 2: AI Configuration

**Goal:** Configure AI providers

**Steps:**
```bash
# Option A: Gemini only (FREE)
quad config set gemini.api_key "YOUR_GEMINI_KEY"
quad config status

# Option B: Both providers (for fallback)
quad config set claude.api_key "YOUR_CLAUDE_KEY"
quad config status

# View all config
quad config list

# Change router mode
quad config set router.mode smart
quad config set router.confidence_threshold 0.7
```

**Expected:**
- API keys masked in output (shows first 10 + last 4 chars)
- Status shows ✓ Set for configured providers
- Router mode updated correctly

---

### Scenario 3: Project Initialization with Hooks

**Goal:** Verify init command captures tech stack decisions

**Steps:**
```bash
# Create test project
quad init banking-demo

# Interactive prompts:
# - Project type: [4] Full Stack
# - Frontend: [1] Next.js
# - Backend: [1] Spring Boot
# - Database: [1] PostgreSQL
```

**Expected:**
- Project created: banking-demo/.quad/config.json
- PRE-HOOK executes (no errors)
- POST-HOOK analyzes context:
  - Topics: ["project"]
  - Decisions: [{"type": "tech_stack", "value": "Spring Boot"}, ...]
  - Preferences: [{"type": "frontend", "value": "Next.js"}]
- Context stored in: ~/.quad/contexts/project.json

**Verify Context Storage:**
```bash
quad context list
quad context show project
```

Should show the tech stack decisions.

### Scenario 4: Story Creation with Context Enrichment

**Steps:**

**Verify:**


### Scenario 6: AI Router - Confidence Fallback

**Goal:** Test Gemini → Claude fallback

**Setup:**
```bash
# Ensure both API keys configured
quad config status  # Both should be ✓ Set

# Set high confidence threshold to force fallback
quad config set router.confidence_threshold 0.95
```

**Steps:**
```bash
# Create a complex story
cd banking-demo
quad story create
# Enter: "implement oauth2 authentication with jwt refresh tokens and role-based authorization"
```

**Expected:**
1. AI Router classifies: "critical" (authentication is critical)
2. Tries Gemini first
3. Checks confidence in response
4. If confidence < 0.95 → Falls back to Claude
5. Uses Claude result

**Verify in logs:**
```bash
# Check context for AI provider used
quad context show project
# Look for "ai_provider": "claude" in recent entries
```

---

### Scenario 7: Router Mode Switching

**Goal:** Test different router modes

**Test Each Mode:**

```bash
# Mode 1: Smart (default)
quad config set router.mode smart
quad story create

# Mode 2: Gemini only
quad config set router.mode gemini_only
quad story create

# Mode 3: Claude only (if API key set)
quad config set router.mode claude_only
quad story create

# Mode 4: Single provider
quad config set router.mode single
quad config set router.default_provider gemini
quad story create
```

**Expected:**
- Smart mode: Uses fallback logic
- Gemini only: Never calls Claude
- Claude only: Never calls Gemini
- Single mode: Uses default_provider only

### Scenario 9: Context Search

**Goal:** Test context search functionality

**Steps:**
```bash

```

**Expected:**

---

### Scenario 10: Error Handling

**Goal:** Verify graceful degradation when hooks/AI fail

**Test Cases:**

**A. Invalid API Key:**
```bash
quad config set gemini.api_key "INVALID_KEY"
quad story create
```
Expected: Shows warning but command continues with rule-based fallback

**B. No API Keys:**
```bash
quad config set gemini.api_key null
quad config set claude.api_key null
quad story create
```
Expected: Uses rule-based analysis, no AI calls

**C. Network Error:**
```bash
# Disconnect internet
quad story create
```
Expected: Falls back to rule-based analysis
