## Multi-Tenant Architecture

### Database Strategy

**Option 1: Shared Database (SaaS)**
```sql
-- Add tenant_id to all tables
CREATE TABLE edu_users (
    phone_number VARCHAR(20),
    tenant_id UUID NOT NULL,  -- Which school?
    name VARCHAR(255),
    ...
    PRIMARY KEY (phone_number, tenant_id)
);

CREATE TABLE edu_tenants (
    id UUID PRIMARY KEY,
    school_name VARCHAR(255),
    domain VARCHAR(255),
    branding JSONB,  -- logo, colors, etc.
    features JSONB,  -- enabled features
    created_at TIMESTAMP
);
```

**Benefits:**
- Cheaper (one database for all)
- Easy updates (update once, affects all)
- Shared infrastructure costs

**Downsides:**
- Data isolation concerns
- One school's spike affects others

**Option 2: Dedicated Database (Enterprise)**
```
delhi-public-school-db
xyz-academy-db
coding-bootcamp-db
```

**Benefits:**
- Complete data isolation
- Custom performance tuning
- Regulatory compliance (GDPR, FERPA)

**Downsides:**
- More expensive
- Updates need to run on each DB

**Our Approach: Hybrid**
- Small schools → Shared database (SaaS)
- Large schools (>5,000 students) → Dedicated database (Enterprise)
